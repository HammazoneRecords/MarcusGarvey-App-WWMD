**Version**: 2.0  
**Status**: CANONICAL  
**Last Updated**: 2025-12-28T18:50:00-05:00

## Purpose

This document defines the **canonical schema** for ingestion receipts in the Solob Wrapper system. Every ingestion operation MUST generate a receipt conforming to this schema to ensure:

- **Legal Defensibility**: Complete audit trail for forensic reconstruction
- **Reproducibility**: Sufficient metadata to reproduce ingestion
- **Traceability**: Link every chunk to its originating session and anchor
- **Validation**: Machine-readable format enables automated compliance checking

---

## Schema Overview

All receipts are JSON files stored in `evidence/{SESSION_ID}/RECEIPTS/`.

**Naming Convention**: `RECEIPT_{INTENT}_{ANCHOR_ID}_{DESCRIPTOR}.json`

**Example**: `RECEIPT_CHUNKS_book_of_solobility_v1_PDF_PAGES_PILOT.json`

---

## Required Root Fields

### Metadata Fields

```json
{
  "receipt_version": "V2",
  "intent": "ARTISAN_PDF_PAGE_CHUNK_PILOT",
  "generated_utc": "2025-12-28T18:39:39Z"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `receipt_version` | string | [OK] | Schema version (always "V2" for this spec) |
| `intent` | string | [OK] | Human-readable intent (e.g., "ARTISAN_PDF_PAGE_CHUNK_PILOT", "LEXICON_IMPORT") |
| `generated_utc` | string | [OK] | Receipt generation timestamp (ISO8601 UTC with Z suffix) |

---

### Session Tracking

```json
{
  "import_session_id": "S_20251225T075155Z_STATE_RECORD"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `import_session_id` | string | [OK] | Canonical session ID (format: `S_<UTC>_<DESCRIPTOR>`) |

---

### Anchor Information

```json
{
  "anchor_id": "book_of_solobility_v1",
  "source_path": "anchors/canon/book_of_solobility/BoS1v1.pdf",
  "manifest_entry_sha256": "ec86c62764501d41676a2237e8ff5c4a21bad3d9525bafa550b12349c9c216bd"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `anchor_id` | string | [OK] | Unique anchor identifier from database |
| `source_path` | string | [OK] | Relative path to source file from repo root |
| `manifest_entry_sha256` | string | [OK] | SHA256 from anchors manifest (for verification) |

---

### Database State

```json
{
  "db": {
    "path": "data/memory.db",
    "chunks_before": 2839,
    "chunks_after": 3446,
    "delta": 607
  }
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `db.path` | string | [OK] | Relative path to database file |
| `db.chunks_before` | integer | [OK] | Chunk count before ingestion |
| `db.chunks_after` | integer | [OK] | Chunk count after ingestion |
| `db.delta` | integer | [OK] | Chunks inserted (must equal after - before) |

---

### Strict Rules

```json
{
  "strict_rules": {
    "chunk_collision": "STOP",
    "missing_anchor": "STOP",
    "missing_pdf": "STOP",
    "manifest_sha_mismatch": "STOP"
  }
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `strict_rules` | object | [OK] | Failure handling rules enforced during ingestion |
| `strict_rules.*` | string | [OK] | All values MUST be "STOP" (no silent failures allowed) |

**Common Rules**:
- `chunk_collision`: Duplicate chunk_id detection
- `missing_anchor`: Anchor not found in database
- `manifest_sha_mismatch`: Source file SHA doesn't match manifest
- `schema_mismatch`: Data doesn't conform to expected schema

## Optional but Recommended Fields

### Timestamps

```json
{
  "timestamps": {
    "start_utc": "2025-12-28T18:39:30Z",
    "end_utc": "2025-12-28T18:39:39Z",
    "duration_seconds": 9
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `timestamps.start_utc` | string | Ingestion start time (ISO8601 UTC) |
| `timestamps.end_utc` | string | Ingestion end time (ISO8601 UTC) |
| `timestamps.duration_seconds` | number | Elapsed time in seconds |

### Ritual Metadata (V2+ for Reality 5)

**Purpose**: Enable ritual engine receipts while maintaining V2 structural compatibility with Reality 4 Court.

Receipts generated by the ritual engine MAY include ritual metadata:

```json
{

    "ritual_name": "lexicon_import",
    "config_hash": "sha256:a1b2c3d4...",
    "config_path": "config/rituals/lexicon_a_template.json",
    "module_name": "lexicon_ingestion",
    "module_version": "1.0"
  }
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `ritual_metadata` | object | [ERROR] Optional | Present only for ritual-executed ingestions |
| `ritual_metadata.ritual_name` | string | [OK] | Ritual identifier (e.g., "lexicon_import", "pdf_chunking") |
| `ritual_metadata.config_hash` | string | [OK] | SHA256 hash of ritual config file (format: "sha256:...") |
| `ritual_metadata.config_path` | string | [OK] | Relative path to ritual config |
| `ritual_metadata.module_name` | string | [OK] | Module that executed the ritual |
| `ritual_metadata.module_version` | string | [ERROR] Optional | Module version if known |

## Validation Rules

### Required Field Validation
- All Required fields MUST be present
- Missing required fields -> Receipt INVALID

### Type Validation
- `chunks_before`, `chunks_after`, `delta` MUST be integers >= 0
- `delta` MUST equal `chunks_after - chunks_before`
- `generated_utc`, `start_utc`, `end_utc` MUST be valid ISO8601 UTC timestamps

### Strict Rules Validation
- `strict_rules` object MUST be present
- All values in `strict_rules` MUST be "STOP"
- Receipts with "WARN", "IGNORE", or other values are INVALID

### Session ID Format
- Pattern: `S_<YYYYMMDDTHHMMSSZ>_<DESCRIPTOR>`
- Example: `S_20251225T075155Z_STATE_RECORD`

## Migration from V1

V1 receipts (informal, undocumented) should be validated for:
1. Presence of `import_session_id`
2. Database delta tracking
3. Strict rules enforcement

V1 receipts that meet these criteria can be considered V2-compatible with minor schema additions.
