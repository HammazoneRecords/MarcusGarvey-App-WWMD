ROADBLOCK PROTOCOL (FOUR-STRIKE RULE)

DEFINITION: A "ROADBLOCK" IS ANY CONDITION THAT PREVENTS FORWARD PROGRESS
WITHOUT NEW HUMAN INFORMATION OR HUMAN-ACTION OUTPUT.

ROADBLOCK TYPES:
- MISSING FILE OR DEPENDENCY
- AMBIGUOUS CANON FILE (MULTIPLE VERSIONS, CONFLICTING PATHS)
- PERMISSION ERROR OR ACCESS ISSUE
- FAILING INVARIANT OR VALIDATION CHECK
- ENCODING CORRUPTION THAT BLOCKS READING
- TOOL OUTPUT CONTRADICTION
- FAILED VERIFICATION WITH NO LOGS
- AMBIGUOUS STATE (CANNOT DETERMINE WHICH DB/SCHEMA/VERSION IS CANON)

CONSECUTIVE DEFINED:
- "CONSECUTIVE" MEANS WITHIN A SINGLE ATTEMPTED FLOW WITHOUT A SUCCESSFUL FORWARD STEP.
- IF PROGRESS IS MADE, THE COUNTER RESETS TO 0.

RULE:
- IF THE AI ENCOUNTERS 4 CONSECUTIVE ROADBLOCKS, IT MUST STOP AND REQUEST USER INPUT.
- THE AI MUST NOT GUESS STATE AFTER STRIKE 4.
- THE AI MUST NOT PROPOSE FURTHER ACTIONS AFTER STRIKE 4.

ON THE 4TH CONSECUTIVE ROADBLOCK, THE AI MUST:
1. STOP PROPOSING FURTHER ACTIONS
2. LOG WHAT IT TRIED AND WHY IT FAILED (NO GUESSING)
3. REQUEST HUMAN INPUT WITH A SHORT MENU OF OPTIONS:
   (a) PASTE COMMAND OUTPUT (STDOUT/STDERR, FIRST 30-80 LINES)
   (b) CONFIRM FILE PATH(S) (WHICH FILE IS CANON, WHERE IT LIVES)
   (c) CHOOSE AMONG 2-3 REPAIR OPTIONS (AI PROPOSES OPTIONS, HUMAN CHOOSES)

COUNTER:
- STRIKE COUNT INCREASES ONLY WHEN THE AI CANNOT PROCEED WITHOUT NEW INPUT.
- STRIKE COUNT RESETS TO 0 WHEN THE USER PROVIDES THE REQUIRED INPUT OR A CONFIRMING OUTPUT LOG.

HUMAN INPUT REQUEST FORMAT:
- MINIMAL AND ACTIONABLE: 1-3 ITEMS MAX
- EACH ITEM MUST BE ANSWERABLE WITH:
  - A COPY/PASTE (LOG SNIPPET, FILE PATH)
  - A YES/NO CONFIRMATION
  - A CHOICE FROM 2-3 OPTIONS
