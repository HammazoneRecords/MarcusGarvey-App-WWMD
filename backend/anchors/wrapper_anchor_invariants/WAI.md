# WRAPPER ANCHOR INVARIANTS
(CANONICAL ? VERSION 1.0)

# PURPOSE
THE ANCHOR FOLDER IS THE CANONICAL MEMORY CORE OF THE SOLOB WRAPPER.
IT STORES READ-ONLY SOURCES OF MEANING THAT THE SYSTEM MAY REFERENCE,
BUT MUST NEVER MUTATE, OPTIMIZE, OR REWRITE.

THE ANCHOR FOLDER IS A SOURCE OF TRUTH.
THE DATABASE IS ONLY AN INDEX.

THESE INVARIANTS DEFINE WHAT MAY NEVER BREAK.




#  INVARIANT:
ALL CONTENT IN THE ANCHOR FOLDER IS READ-ONLY AT RUNTIME.

NO PROCESS, SCRIPT, OR AGENT MAY:
- MODIFY FILE CONTENT
- OVERWRITE FILES
- NORMALIZE TEXT
- AUTO-CORRECT LANGUAGE
- REFORMAT STRUCTURE

RATIONALE:
ANCHORS ARE MEMORY, NOT WORKSPACE.





# INVARIANT:
THE DATABASE MAY REFERENCE ANCHORS,
BUT ANCHORS MUST NEVER DEPEND ON THE DATABASE.

IF THE DATABASE IS DELETED,
THE ANCHOR FOLDER MUST REMAIN SUFFICIENT
TO REBUILD THE SYSTEM.

RATIONALE:
MEMORY MUST SURVIVE INDEX FAILURE.




# INVARIANT:
TEXT INSIDE ANCHOR FILES MUST REMAIN VERBATIM.

THIS INCLUDES:
- SPELLING
- GRAMMAR
- PATOIS
- INFORMALITY
- INCONSISTENCIES
- AUTHORIAL VOICE

NO AUTOMATED CLEANUP IS PERMITTED.

RATIONALE:
WORDING CONTAINS CONTEXT THAT CANNOT BE REGENERATED.




# INVARIANT:
CORRECTIONS, CLARIFICATIONS, OR DISPUTES
MUST NEVER BE APPLIED INSIDE ANCHOR FILES.

ALL CORRECTIONS MUST BE EXPRESSED AS:
- PROVENANCE NOTES
- ANNOTATIONS
- METADATA
- DATABASE-LEVEL REFERENCES

RATIONALE:
ANCHORS REMEMBER HISTORY; ANNOTATIONS INTERPRET IT.




# INVARIANT:
EVERY ANCHOR MUST BE CLASSIFIABLE BY ROLE.

VALID ROLES INCLUDE (BUT ARE NOT LIMITED TO):
- LEXICON
- BOOK
- LETTER SET
- CANON TEXT
- WORKING DRAFT

ROLE IS DECLARED IN METADATA,
NOT INFERRED BY CONTENT.

RATIONALE:
MEANING MUST NOT BE GUESSED.



# INVARIANT:
ANCHOR CONTENT MUST NEVER EXECUTE LOGIC.

ANCHORS MUST NOT:
- TRIGGER ACTIONS
- CONTAIN CONTROL DIRECTIVES
- ACT AS PROMPTS
- MODIFY SYSTEM STATE

THEY MAY BE:
- READ
- QUOTED
- REFERENCED
- INDEXED

RATIONALE:
LANGUAGE SHOULD INFORM SYSTEMS,
NOT SECRETLY CONTROL THEM.


# INVARIANT:
ADDING A NEW ANCHOR REQUIRES EXPLICIT DECLARATION OF INTENT.

EACH ADDITION MUST RECORD:
- SOURCE
- PURPOSE
- DATE
- STATUS (CANON / WORKING)

SILENT INSERTION IS FORBIDDEN.

RATIONALE:
MEMORY GROWS BY CHOICE, NOT ACCIDENT.



# INVARIANT:
ANCHORS MUST NOT BE DELETED BY DEFAULT.

DEPRECATION IS EXPRESSED VIA:
- STATUS CHANGES
- DATABASE FLAGS
- EXTERNAL NOTES

PHYSICAL DELETION IS A LAST RESORT
AND MUST BE MANUAL AND EXPLICIT.

RATIONALE:
FORGETTING SHOULD BE CONSCIOUS.


# INVARIANT:
NO AUTOMATED PROCESS MAY PROMOTE, DEMOTE,
OR REINTERPRET ANCHORS WITHOUT HUMAN REVIEW.

AUTOMATION MAY:
- INDEX
- SUMMARIZE
- REFERENCE

HUMANS ALONE:
- DECLARE CANON
- RESOLVE MEANING
- AUTHOR TRUTH

RATIONALE:
TOOLS PRESERVE MEMORY.
HUMANS DEFINE IT.


# INVARIANT:
COHERENCE IS PRIORITIZED OVER COMPLETENESS.

IT IS BETTER TO HAVE:
- FEWER ANCHORS
- WELL UNDERSTOOD
- PROPERLY PROVENANCED

THAN MANY ANCHORS
WITH UNCLEAR STATUS OR ROLE.

RATIONALE:
SUITABILITY OUTRANKS VOLUME.


# INVARIANT: INVARIANT FILES ARE APPEND-ONLY AND VERSIONED

ANY UPDATE TO AN INVARIANT FILE (INCLUDING THIS FILE)
MUST NEVER DELETE OR OVERWRITE A PREVIOUS VERSION.

WHEN AN INVARIANT FILE IS UPDATED:

- THE EXISTING FILE MUST BE MOVED TO AN ARCHIVE FOLDER
- THE ARCHIVED FILE MUST RETAIN:
  - ORIGINAL FILENAME
  - ORIGINAL VERSION IDENTIFIER
  - ORIGINAL TIMESTAMP
- THE NEW FILE BECOMES THE ACTIVE VERSION

SUGGESTED STRUCTURE:

/anchors/
  ??? WAI.md                (ACTIVE)
/anchors/archive/
  ??? WAI_v1.0_2025-12-19.md
  ??? WAI_v1.1_2026-01-xx.md

NO AUTOMATED PROCESS MAY:
- DELETE ARCHIVED INVARIANT FILES
- MODIFY ARCHIVED CONTENT
- COLLAPSE VERSION HISTORY

RATIONALE:
INVARIANTS ARE LOGIC ARTIFACTS.
THEIR EVOLUTION MUST REMAIN TRACEABLE.

LOGIC WITHOUT HISTORY BECOMES DOGMA.




# CLOSING PRINCIPLE

THE ANCHOR FOLDER EXISTS TO REMEMBER HONESTLY,
NOT TO OPTIMIZE, CORRECT, OR IMPRESS.

IF THESE INVARIANTS ARE BROKEN,
THE SYSTEM MAY APPEAR INTELLIGENT
BUT WILL NO LONGER BE TRUSTWORTHY.
