### Database State Tracking Pattern

**Implementation**:
```python
# Before
chunks_before = conn.execute("SELECT COUNT(*) FROM chunks").fetchone()[0]

# Perform insertion
inserted = insert_chunks(...)

# After
chunks_after = conn.execute("SELECT COUNT(*) FROM chunks").fetchone()[0]
delta = chunks_after - chunks_before

# Defensive verification
if delta != inserted:
    raise RuntimeError(f"STOP: database delta mismatch (expected={inserted}, actual={delta})")
```

**Benefits**:
- Catches silent failures
- Proves insertion success
- Documents database state changes
- Enables forensic reconstruction

## Lessons Learned

### 1. Mandatory Receipts Prevent Data Loss
Making receipt generation required (not optional) ensures no ingestion operation goes undocumented. Future forensic investigations will have complete trails.

### 2. Database Delta Verification Catches Bugs
The pattern of comparing expected vs actual database deltas has already caught subtle bugs in other projects. Defensive programming pays dividends.

### 3. Standardization Enables Automation
Uniform bundle layouts made weekly aggregation trivial. Consistency multiplies automation opportunities.

### 4. V2 Schema Migration is Smooth
Grandfathering V1 bundles (WARN, not FAIL) allows gradual migration without breaking existing workflows. New bundles are V2, old bundles remain valid.
