## Technical Details

### State History Format V1.0 Specification

The canonical format enforced by `tools/validate_state_history_format.py`:

```
- YYYY-MM-DDTHH:MM:SS-05:00 (UTC YYYY-MM-DDTHH:MM:SSZ) - STATE1 -> STATE2 - Reason text (sid=S_TIMESTAMP_DESCRIPTOR)
```

**Key Requirements**:
- Local Kingston time (-05:00) followed by UTC (Z) in parentheses
- State transition format: `FROM -> TO`
- Single-line reason (no multi-line entries)
- Mandatory SID for post-epoch entries (after 2025-12-25T07:51:59Z)
- NOTE entries for non-transition events

### Helper Script Architecture

**log_state_transition.py**:
- Reads `docs/STATE.json` to fetch active_session_id
- Generates timestamps using `datetime.now(timezone.utc)` with -5 hour offset
- Appends to STATE_HISTORY.md with proper formatting
- Supports `--note`, `--from`, `--to`, `--reason`, `--sid` arguments
- Exit code 0 on success, 1 on invalid arguments

**Witness Epoch Policy**:
1. Transition notes must include canonical SID that witnessed the window
2. SID generated during transition to RECORD
3. Same SID logged during transition back to OBSERVE to seal the window
4. Verification helper: `tools/verify_witness_epoch.py`

### Bundle Migration Strategy

**V1 to V2 Upgrade Path**:
1. Identify bundles lacking INDEX.json
2. Extract metadata: Session ID, Timestamp, Descriptor from folder name
3. Recover internal metadata from BATCH_RECEIPT.json if present
4. Generate INDEX.json with type="grandfathered_v1"
5. Generate REPORT.md summarizing migration and validity
6. Verify with court_sweep.py
