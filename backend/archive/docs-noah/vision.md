## 3. Foundational Principles

### 3.1 Witness Over Convenience
Nothing meaningful enters the system without:
- An anchor
- A session
- A receipt

Speed without witness is how hallucinations are born.

---

### 3.2 Suitability Over Completeness
The system does not aim to store *everything*.
It aims to store **what fits**.

- Chunks must be justified
- Anchors must exist
- Derivatives must point backward

Completeness is optional.  
**Coherence is not.**

---

### 3.3 Canon vs Derivative (Never Confused)
- **Canon**: Anchors, DB, evidence, governance
- **Derivative**: Chunks, embeddings, runs, exports
- **Surface**: APIs, UI, tools

Canon is sacred.  
Derivatives are reproducible.  
Surfaces are replaceable.

## 5. STGRAIL: State Discipline

All system actions are governed by explicit state:

- **OBSERVE**

This is not a suggestion.

State discipline ensures:
- No accidental writes
- No silent corruption
- No ambiguous timelines
